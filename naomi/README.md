# Marvel vs. Capcom 2 — NAOMI decompilation

A matching decompilation of the arcade (Sega NAOMI) program. C is compiled
with the original Hitachi SH C compiler and must reproduce the retail ROM byte
for byte. Only whole sections that match exactly are credited as verified.

The ROM, the compiler and Sega's SDK libraries are not in the repository; see
[docs/BUILD_INPUTS.md](docs/BUILD_INPUTS.md). With them in place:

```sh
cd naomi
python3 tools/build.py check
```

That verifies the inputs, runs the tests, compiles every registered unit, links
each at its original address, compares the result with retail, and rebuilds the
program ROM.

- **Map**: bytes of the main image reviewed as code or data (`config/mapping.json`).
- **Matched reviewed code** and **Data**: reviewed bytes the build reproduces
  exactly, from checked-in C or by linking the prebuilt Sega SDK module the
  retail ROM itself linked.
- **Decomp**: both together, against the whole 2,424,832-byte main image.
- **Verified C code + data**, **Prebuilt SDK modules** and **Candidate
  fragments**: separate contributions to Decomp, each against the whole image.
- **Verified C executable code (lower bound)** excludes SDK objects, candidate
  fragments and data. Its denominator counts unknown bytes as potential code.

The table is generated by the build (`tools/report.py`); do not edit it by
hand. `build/index.html` is a treemap from the same build.

## What it is for

The playable port in [`../port`](../port) runs the PS2 program, because the
PS2 decompilation is complete and this one is not. The arcade is the behaviour
the port aims for: the NAOMI oracle (`port/tools/naomi_oracle`) runs this ROM
in Flycast and compares it with the port, and
[`port/docs/ARCADE_DIFF.md`](../port/docs/ARCADE_DIFF.md) lists what differs
and how the port follows the arcade.

## Layout

| Path | Holds |
| --- | --- |
| `config/target.json` | The reference ROM set and the main image location |
| `config/compiler.json` | The two option sets every unit uses (`game`, `library`) |
| `config/mapping.json` | Reviewed code and data ranges with their evidence |
| `config/units.json` | Every unit, its original addresses, exports and imports |
| `src/include/` | Shared object definitions |
| `src/verified/` | Units that match retail |
| `src/candidates/` | Units that do not match yet, each saying what differs |
| `tools/` | Build, verifier, diff, draft, search and recovery tools |
| `toolchain/` | Compiler and SDK manifests, and the wibo runtime |
| `tests/` | Checks on the verifier and the mapping |
| `build/` | Generated; never committed |
