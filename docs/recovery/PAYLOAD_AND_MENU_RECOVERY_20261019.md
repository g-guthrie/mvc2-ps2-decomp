# Payload callbacks and menu resources

Four independently referenced callbacks add 1,020 exact code bytes. All use the 196-byte payload aggregate already established by adjacent recovered initializers. `00198730` and `001BAA10` compile with MWCCPS2 3.0-011126, `-O3 -Op -sdatathreshold 0`; `001CBEF0` and `001E0D90` use the same compiler with small-data threshold 8. Entries and preceding dispatchers are recorded in INDEPENDENT_CALLBACK_ENTRIES.csv. Owner A1 for 001BAA10 comes from 001BA660 through 001BA9F0; owner A1 for 001E0D90 comes from 001E0AC0 through 001E0D70. The actual 001754A0 declaration returns s32 and accepts two u8 selectors.

New reconstructed data totals 667 bytes: 31 terminated menu/debug strings (363 bytes), 37 eight-byte button-render descriptors (296 bytes), and two scalar callback pointers (8 bytes). Alignment gaps remain uncredited. The descriptor tail begins at 004B9208 and ends at the independently referenced 004B9330 switch table. Native 003D4290 addresses the tail; recovered 003D4AD0 uses the broader record family and 003D4950 establishes the eight-byte layout. Resource pointer fields resolve to terminated formatting strings. This establishes the physical resource family, not a universal runtime selector bound.

Only the scalar pointers at 004C1F78 and 004C1F88 are reconstructed within the withdrawn 72-byte state-data interval. Their targets are residual_003AFA90 and residual_003B0900. The remaining 64 bytes stay raw and uncredited. Source declarations now describe scalar fields; existing unchecked indexed access is retained without inventing a two-entry table extent. The data symbol generator recognizes existing residual labels; a regression fixture proves their relocation addresses survive normal map generation.

Validation: production-compiler replay of all changed code units and 63 changed data objects; exact 3,941,760-byte loaded ROM and 3,942,320-byte packed retail ELF; 55 project tests plus two Sony tooling tests; catalog, build coverage, shell syntax, and whitespace checks. Code reaches 1,926,772/3,293,696 bytes (58.4988%); reconstructed data reaches 177,259/648,064 (27.3521%). This is a local checkpoint below the next publication threshold of 1,948,762 code bytes.

A later callback batch recovers 001BAEE0 (308 bytes) and 001C1470 (276 bytes), also with MWCCPS2 Version 3.0, runtime built November 26, 2001, O3/Op/G0. The first uses the owner supplied by native 001BAE90: it loads A1 from p+0x18, selects 0044C010[0] -> 001BAEC0, then 0044C030[0] -> 001BAEE0. The existing intermediate source dispatcher now explicitly propagates this second argument; all 1,432 functions in its source unit still verify exactly. The initializer copies the owner position and applies a facing-dependent 60-unit offset before selecting animation and alpha. The second callback has a unary entry at 0044C880[0], preceded by 001C1450; it copies the owner's payload, selects mode 0x1C01, and chooses animation 1 or 2 from its own byte 0x20. Both downstream update-function signatures were checked against their recovered definitions. Unknown adjacent functions receive no credit.
